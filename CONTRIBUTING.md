Software Engineering, Fall 2026

This page covers how we work in the repo so `main` stays stable and nobody is blocked.

## The Basics

- `main` is protected. All changes go through a pull request (PR).
- Every PR needs 2 approvals before it can be merged.
- Never approve your own PR.

## Branch Naming

Create one branch per task, off the latest `main`, using `type/short-description` in lowercase with hyphens.

Example: `feature/recipe-generation`

Common types: `feature/`, `fix/`, `docs/`, `setup/`.

## Pull Request Process

1. Pull the latest `main` and create your branch.
2. Commit in small, focused chunks with clear messages.
3. Push your branch and open a PR into `main`.
4. In the PR description, say what changed and why.
5. Request review from your teammates.
6. Address review comments by pushing new commits to the same branch.
7. After 2 approvals, the PR author merges and deletes the branch.

## Review Expectations

- Review PRs within 1 day of being asked, so nobody is blocked.
- Check that the change does what the description says and the code or docs are readable.
- Leave specific, constructive comments. Approve when you would be comfortable shipping it.
